# P3 · أمن بيانات اعتماد Stitch

فحص محلي في 10 نوفمبر 2026. جميع المطابقات تمت داخل العملية. `K1` تسمية مرجعية داخل الفحص لقيمة مطابقة وليست بصمة أو جزءاً منها. لم تُختبر صلاحية أي قيمة عند Google.

ظهرت قيمتان حرفيتان مختلفتان بين خمسة ملفات JSON. تُستخدم القيم كرأس اعتماد HTTPS لخادم Stitch. تسجيل API key header لا يثبت أن الاعتماد صالح أو مقيّد بالمشروع، ولذلك تُعامل القيمتان كأسرار.

## نطاق التعرض

- **سجل Claude** تطابق حرفياً مع قيمة ملف المشروع في `C:\Users\asus\.claude\projects\D--GoogleAntigravity-VoiceStudio-main\10762a9c-0915-4ad0-8e1a-2c0bc167dd20.jsonl`. ACL السجل يتيح قراءة موروثة لـ`CodexSandboxUsers` إضافة إلى الحساب المالك وSYSTEM وAdministrators. ظهر التطابق في إدخال واحد من نوع user في سجل الجلسة. هذا يثبت وجود نسخة في سجل محلي، ولا يحدد وحده أي طرف قرأها أو أرسلها خارج الجهاز.
- **Git في casher** لم يكن `.mcp.json` متتبعاً، ولم يظهر له commit ضمن المراجع المحلية. فُحص 2,289 كائناً من المراجع المحلية ومرحلة الفهرس، منها 1,200 blob. لم يظهر تطابق حرفي للقيمتين. لم يُنفذ fetch أو استعلام لمستودع بعيد.
- **سجلات Codex المفحوصة** لم يظهر تطابق في عينة الجلسات وقواعد logs_2 وملف WAL الذي أمكن فحصه. لم يظهر تطابق أيضاً في 160 ملف سجل حديثاً لـAntigravity. فحص تخزين محادثات Antigravity الكامل لم يكتمل. لا تغطي المطابقة الأرشيفات المضغوطة أو المزامنة الخارجية.
- **النسخ والمشاركة** أربع ملفات Antigravity الحالية والتاريخية تحمل قيماً حرفية. المسارات المفحوصة على D تقع على قرص NTFS محلي ولا تظهر كـreparse points في جذورها. تعذر تعداد SMB على مستوى النظام ضمن الصلاحيات المتاحة، ولذلك لا يوجد حكم على جميع المشاركات والنسخ البعيدة.

## معالجة مقترحة بعد موافقة منفصلة

1. حدد مالك كل اعتماد ونطاقه ومن يحتاجه. راجع الوصول إلى السجل المطابق والنسخ المحلية ضمن صلاحيات المستخدم، واعزل الملف عند الاتفاق على سياسة الاحتفاظ.
2. جهّز اعتماد اختبار منفصلاً ومحدود النطاق. اختبر تخزينه عبر Windows Credential Manager أو مخزن DPAPI مربوط بالمستخدم مع ACL محدد، أو مخزن المؤسسة المعتمد. لا تمرر القيم في وسيطات الأوامر ولا تخزّنها في PowerShell profile أو متغير مستخدم دائم.
3. اقرأ القيمة عند بدء عميل معتمد وحقنها في بيئة العملية المعنية فقط. Codex يدعم `env_http_headers`. تحقق من دعم التوسيع في Claude وAntigravity على إصدار كل عميل باستخدام قيمة اصطناعية أولاً. إذا كان السطح يتطلب قيمة حرفية فاستعمل وسيطاً محلياً مصادقاً ومدققاً بدلاً من وضع سر جديد في JSON.
4. بعد موافقة صاحب الاعتماد، دوّر القيم المعنية، خصوصاً القيمة المطابقة في السجل. قيّد المفتاح عند المزود بما يحتاجه Stitch فعلاً، واختبر كل عميل في جلسة جديدة، ثم عالج النسخ الاحتياطية والسجلات وفق سياسة الاحتفاظ.
5. خطة التراجع هي الرجوع إلى مرجع التخزين السابق خلال نافذة اختبار معتمدة. تدوير المفتاح عملية مستقلة. الاعتماد الذي أُلغي لا يعود صالحاً باسترجاع الملف.
