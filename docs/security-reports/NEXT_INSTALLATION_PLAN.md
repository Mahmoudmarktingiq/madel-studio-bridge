# خطة المرحلة التالية وأفضل 15 إضافة

هذه خطة للمراجعة بعد الموافقة. الأولوية لإعادة استخدام ما أثبت التدقيق توفره. المرشحون المسمّون «مهارة محلية» مواصفات جديدة مقترحة، ويُراجع مصدرها وكودها قبل إضافتها.

## المرشحون بالترتيب

| # | الأداة أو المهارة | المصدر المقترح | الفجوة ومعيار القبول |
|---|---|---|---|
| 1 | MCP Inspector CLI | [مشروع MCP الرسمي](https://github.com/modelcontextprotocol/inspector) | فحص `initialize` و`tools/list` محلياً على خادم معروف، مع فصل استعراض الأدوات عن استدعائها |
| 2 | Windows MCP Audit | مهارة محلية | جرد JSON/TOML/JSONC وPATH والمنافذ. تطبع أسماء الحقول ولا تعرض أسراراً |
| 3 | MCP Fixture & Regression | مهارة محلية | حزم fixtures واختبارات رفض أدوات الكتابة والتأكد من عدم وجود تغييرات خارج العينة |
| 4 | Dependency & Provenance Review | مهارة محلية | بصمة المصدر والـlockfile والاعتماديات المتداخلة، وقرار منع تفعيل قابل للتدقيق |
| 5 | Blender Safe Session | مهارة محلية فوق MCP الموجود | رصد الإصدار وحالة الاتصال، وفصل القراءة عن الكتابة، وعميل كتابة واحد |
| 6 | Comfy MCP المحلي | [Comfy-Org](https://github.com/Comfy-Org/comfy-mcp) | يكتشف API Desktop الموجود ويعرض الأدوات بنجاح من عميل واحد دون إرسال workflow |
| 7 | Comfy Workflow Preflight | مهارة محلية | تتحقق من الأنواع والنماذج والعقد وإعداد CPU قبل وضع مهمة في الطابور |
| 8 | CapCut Draft QA | مهارة محلية تكمل `capcut-edit` | تقارن root وTimelines وjournal، وتحدد نسخة المحرر، وتنتج ملخصاً دون كتابة |
| 9 | FFprobe Media QC | مهارة محلية فوق FFmpeg الموجود | تتحقق من الترميز والدقة والإطارات والقنوات باستخدام مخرجات JSON محلية |

| 15 | Premiere Sequence QA | مهارة محلية | تستعلم عن التسلسل والمسارات والوسائط المفقودة على مشروع اختبار دون تصدير |

## ترتيب التنفيذ بعد الموافقة

1. **حصر P0.** راجع وصول ملفات Stitch والرؤوس والنسخ التاريخية، واختر آلية الاعتماد المناسبة لكل عميل. جهّز تقرير اعتماديات Adobe للشجرة الرئيسية وشجرة الاختبار. لا تُفعّل Brainferno قبل معالجة Zod المتداخل وتقييم امتيازات UXP وCOM.
2. **خط أساس معزول.** اختر مجلد fixtures خارج المشاريع الأصلية، ومشهد Blender وملفات Adobe وCapCut اصطناعية، واعتمد بصمات النسخ قبل الاختبار. جهّز Inspector وأدوات الرصد والتراجع من مصادرها الرسمية فقط بعد الموافقة.
3. **Blender أولاً.** حافظ على loopback، وحدد إصداراً واحداً للحزمة مطابقاً للملحق. بعد ذلك جرّب استعلام الحالة في Claude ثم Codex ثم Antigravity. دوّن النقل والإصدار والنتيجة، وقيّد الكتابة بعميل واحد.
4. **CapCut وFFmpeg.** افحص `describe` و`doctor` عند السماح بالتشغيل، ثم `diagnose` على نسخة مسودة. قارن اختلاف root وTimelines وjournal قبل قرار المزامنة. طبّق المهارات محلياً واختبر ترجمة عربية على عينة منفصلة.
5. **ComfyUI.** شغّل Desktop واعثر على عنوان loopback الفعلي. تحقق من الإصدار والنماذج عبر API للقراءة. إذا كان الإصدار متوافقاً، أضف `comfy-mcp` إلى عميل واحد بتثبيت إصدار محدد، وتحقق من الأدوات قبل أي توليد. وسّع إلى العملاء الآخرين بعد نجاح العينة.
6. **Adobe أخيراً.** بعد مراجعة P0، جرّب `initialize` و`tools/list` على نسخة معزولة. احتفظ بالمصادقة وloopback، وأبقِ raw scripts وinsecure وHTTP الخارجي معطلة. ابدأ باستعلام Photoshop، ثم استعلام Illustrator COM، ثم استعلام Premiere. تحقق من نسخة منفردة للـhandshake قبل مشاركة العميل.
7. **تنظيف منطقي بعد القبول.** حدّد ملفات التكوين الفعلية وراجع تكرار مهارات CapCut ووكلاء المشاريع وVisualize. اختر تثبيت CLI مستقل لـCodex أو Antigravity فقط إذا تطلب العمل ذلك. اعتمد كل تغيير تكوين على حدة مع نسخة قابلة للاسترجاع.

## نقاط التوقف

أوقف التوسع عند اختلاف الإصدار، فشل المصافحة، طلب صلاحية جديدة، الوصول إلى مشروع حقيقي، اختلاف بصمة نسخة اختبار دون سبب، أو الحاجة إلى معالجة اعتماد. يتطلب أي تثبيت أو تعديل إعدادات أو تشغيل سكربت تحكم موافقة مرحلة التنفيذ.
