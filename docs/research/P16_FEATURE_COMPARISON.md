## 2. تحليل القواسم المشتركة بين المشاريع الثلاثة

1. **الاعتماد الصارم على بروتوكول MCP القياسي:**
   كافة المشاريع تتحدث JSON-RPC وتتبع معايير Model Context Protocol (2024-11-05).
2. **عزل خوادم MCP عن مساحة الـ UI Thread للبرامج:**
   جميع المشاريع تشغل خادم MCP كعملية مستقلة خارج نطاق واجهة المستخدم لبرامج التصميم، لضمان عدم تجميد واجهة التطبيق.
3. **الحاجة الملحة لإدارة إعدادات العملاء وتجنب التضارب:**
   المشاريع الثلاثة تؤكد أن العائق الأكبر أمام المستخدم هو إعداد ملفات JSON / TOML الخاصة بعملاء الذكاء الاصطناعي يدوياً، وتوفر حلولاً للمزامنة التلقائية.
4. **تأمين الاتصال المحلي (Loopback Only):**
   حظر الاتصالات الشبكية المفتوحة وحصر الـ Sockets في `127.0.0.1`.

## 3. الفجوات الرئيسية التي تنقص MADEL ومقارنتها بالأولويات

1. **غياب إدارة سقف التزامن والتحكم في إلغاء الطلبات (Concurrency Limiting):**
   - في حال إرسال عميلين طلبين ثقيلين في نفس اللحظة إلى خادم Photoshop، قد يتأخر الرد ويتسبب في Timeout للعميل.
   - **الحل المقترح لـ P17:** تبني نمط `WorkLimiter` و `AsyncLocalStorage` للتحكم الدقيق في الطوابير وإلغاء العمليات المنقطعة.
2. **غياب السجل الشامل لاكتشاف وتحديث العملاء تلقائياً (Automated Client Sync):**
   - حالياً يتم تحديث الإعدادات بسكربتات موجهة.
   - **الحل المخطط لـ P18:** تبني السجل التصريحي الشامل لـ Vinkius (`ClientDefinition`).
3. **عدم وجود واجهة رسومية خفيفة (Desktop GUI):**
   - **الحل المخطط لـ P19:** بناء تطبيق مكتبي بـ Tauri v2 مستوحى من كفاءة Vinkius.
4. **عمق أدوات Photoshop المتقدمة (Smart Objects & Filters):**
   - **الحل المخطط لـ P20:** توسيع أوامر BatchPlay داخل لوحة UXP مستوحى من مهارات `dcc-mcp-photoshop`.
