## 2. ExtendScript ES3 vs. UXP Action Model

### 2.1 Technical Constraints of After Effects
Unlike Adobe Photoshop and Adobe Premiere Pro (which support modern UXP V2 APIs with V8 JavaScript), Adobe After Effects continues to rely primarily on **ExtendScript (ECMAScript 3)** for deep composition, effect parameterization, shape rigging, and timeline keyframing.

Key technical requirements for the ES3 execution model:
1. **No ES6+ Constructs in Host Scripts**: The host engine rejects arrow functions (`() => {}`), `let`/`const`, template literals, and `Promise`. All host code generated by MADEL Studio Bridge strictly uses `var`, function expressions, and ES3 idioms.
2. **Atomic Undo Encapsulation**: Every single mutation tool call is wrapped inside an `app.beginUndoGroup(...)` / `app.endUndoGroup()` block. This ensures that any compound operation performed by an AI client corresponds to exactly one `Ctrl+Z` in the After Effects UI.
3. **Preamble Injections**: Each evaluated script injects a standardized lightweight preamble (`__comp`, `__layer`, `__compNamed`, `__layerNamed`, `__undo`, `__layerInfo`) ensuring deterministic reference lookups by either 1-based numeric index or exact case-sensitive string name.

### 2.2 Host Transport Decoupling
To ensure future compatibility with emerging After Effects UXP APIs, all tools communicate through the abstract `@madel/after-effects-adapter` interface. The tool contracts (`ae_add_text_layer`, `ae_set_position`, `ae_render_comp`) remain immutable regardless of whether the transport executes via ExtendScript COM, UXP WebSocket, or headless CLI.

## 4. Concurrency & Resource Scoping Policy

In accordance with MADEL Gateway Concurrency Architecture (`P17_RECOMMENDATION.md` and `CONCURRENCY_POLICY.md`):
- All composition mutation tools (`ae_create_*`, `ae_add_*`, `ae_set_*`, `ae_rename_*`, `ae_delete_*`) map to the resource scope `after_effects:mutation`.
  - Concurrency: `1`
  - Max Queue Size: `100`
  - Queue Wait Timeout: `30,000 ms`
  - Execution Timeout: `60,000 ms`
- All rendering tools (`ae_render_comp`, `ae_render_frame`, `ae_queue_render`, `ae_inspect_render_queue`, `ae_inspect_render_result`) map to the resource scope `after_effects:render`.
  - Concurrency: `1`
  - Max Queue Size: `20`
  - Queue Wait Timeout: `120,000 ms`
  - Execution Timeout: `600,000 ms`

## 5. Destructive Safety & Guard Rails

1. **`ae_delete_layer`**: Requires affirmative boolean flag `confirm: true`. Calls omitting this parameter or passing `false` are rejected with:
   > `Action cancelled: ae_delete_layer requires confirm: true to prevent accidental data loss.`
2. **`ae_render_comp`**: Requires affirmative boolean flag `approved: true`. Calls omitting this parameter or passing `false` are rejected before project save or process execution with:
   > `Render aborted: parameter 'approved: true' is required to execute headless render via aerender.`
3. **`ae_run_script`**: Guarded by `rawScriptApps` configuration gate. Remote sessions require `BRAINFERNO_MCP_ALLOW_REMOTE_RAW_SCRIPTS=true`. Script content that closes or replaces projects requires explicit operator consent (`allowProjectSwitch: true`).
